# UX Audits — Impulso Builder Platform

Práctica permanente desde Epic 5: al cerrar cada gran bloque funcional (Workspace, Editor, Export, etc.), se realiza una auditoría de UX **independiente de la implementación** — no modifica código, no propone refactors arquitectónicos, no abre épicas nuevas. Su único objetivo es detectar oportunidades de mejora de experiencia antes de que se acumulen, evaluando el bloque como lo haría un equipo de UX de una herramienta profesional de referencia (Figma, Illustrator, Canva, Kittl).

Cada auditoría responde, como mínimo, estas diez dimensiones (ver `docs/ENGINEERING_STANDARDS.md`, "Evaluación dual: Arquitectura + UX"):

1. Tiempo/clics para completar la acción principal del bloque.
2. Descubribilidad de las acciones principales.
3. Claridad visual de la jerarquía.
4. Consistencia con el resto del producto.
5. Cantidad de clics necesarios para cada acción.
6. Posibles confusiones con otras piezas del producto.
7. Comportamiento esperado por un usuario nuevo.
8. Comportamiento esperado por un usuario experto.
9. Accesibilidad (teclado, lectores de pantalla).
10. Oportunidades de simplificación.

Y se entrega siempre en el mismo formato: qué funciona muy bien, qué puede mejorar, quick wins (<30 min), cambios medianos, y cambios grandes que esperan una épica futura. Las auditorías alimentan decisiones de producto — no son, en sí mismas, un compromiso de implementación.
